* Module layout
Directories separate implementation, selection, and construction:

- =modules/features/=: what a capability installs and configures. Each named
  Home Manager module owns a cohesive feature, including its packages, settings,
  and supporting files. For example, =proton-pass.nix= owns both Proton clients;
  =shell/fish.nix= owns Fish and its prompt integrations. Features may also
  contribute build dependencies through the shared flake-level overlays option.
- =modules/profiles/=: which features belong together, plus their shared policy.
  =common.nix= imports the features every current host gets and sets baseline
  policy such as =home.stateVersion=. Put shared feature selection here, not
  individual application configuration.
- =modules/flake/=: how the configuration is assembled and exposed as flake
  outputs. =flake-parts.nix= enables module exports and Home Manager outputs;
  =home.nix= defines =mkHome= and the shared overlays option. This layer constructs
  Home Manager configurations without choosing their applications.

=modules/machines/= supplies each host's system, user, home directory, and module
selection to =mkHome=. =modules/platform/= owns Linux- or Darwin-specific policy.
For example: a machine selects =common= plus =linux=; =common= selects =fish=;
=fish= defines the shell setup; =mkHome= assembles the resulting configuration.

These directories are organizational, not a new module system. =import-tree=
still discovers all Nix files recursively. Named Home Manager modules take effect
when selected through imports; flake-level contributions such as overlays still
merge globally. Moving a file does not rename its exported module.

* Common home policy
=modules/profiles/common.nix= selects shared features and owns =home.stateVersion=,
release-check policy, session path, and Home Manager enablement for all hosts.
=modules/flake/home.nix= handles home construction and overlay composition.
The former =base= module is no longer exported; consumers should select =common=.

* Application inventories
=modules/features/cli-tools.nix= owns terminal tools; =modules/features/desktop-apps.nix= owns
graphical applications. =common= selects both, preserving desktop apps on all hosts.
=modules/features/proton-pass.nix= owns the password-manager experience: =proton-cli= and
the =proton-pass= desktop app, selected together by =common=.
=modules/features/own-apps.nix= selects the default input-backed packages for dime, donies,
sesame, spotify-dl, and worker.

* Linux voice typing
The =whisper= feature installs the local model and =voice-type=. Key injection
uses =xdotool= through the current X11 session; no input daemon, udev rule or
=/dev/uinput= permission is required.

Run =voice-type= in Ghostty to record from the default PipeWire microphone.
While recording, it transcribes all audio so far about every two seconds and
types the result into the focused window. When the recognizer changes earlier
words, it deletes its own text back to the first difference with Backspace and
types the new ending. While recording, punctuation and capitals are left as
first typed; the last pass corrects them, which can retype most of the text.
After sound above the threshold starts, near-silence stops
recording; a last pass over the full audio applies the final correction. Tune
=SILENCE_STOP_DURATION_SECONDS= in the public section of
=modules/features/whisper/config.py=, imported by both the Python implementation
and its tests. Private protocol constants live in a separate section of that
module. Press Enter to stop sooner, or Ctrl+C
to cancel.

Do not type, move the cursor or press Enter while dictating: Backspace would
delete the wrong characters. Dictation stops when another window gets focus.
The command removes control characters and never sends Enter. Temporary audio
and transcripts are removed when it exits.

The English model can misrecognize words; review inserted text before submitting.
Silence detection defaults to 0.5% signal amplitude, which fits normal speech
in a quiet room. =VOICE_SILENCE_THRESHOLD= sets the threshold (for example,
=3%= with background music). Quiet music
below this level does not reset the timer; louder music does. A high threshold
can miss quiet speech. This detects sound levels, not speech versus music.
Text is typed as X11 key presses through =xdotool=; the clipboard is not
touched. Typing on the German layout is not verified yet.
Desktop shortcut wiring is separate. Script checks run during the package build
and import the shared config module, including the tuned silence duration; they can
also run directly:

#+begin_src sh
python3 /home/christian-koestlin/.config/home-manager/modules/features/whisper/test-voice-type.py
#+end_src

The Awesome configuration binds Super+S to start and stop recording
without opening a terminal. It runs =voice-type --hotkey= and sends =SIGUSR1=
to stop recording. Status notifications distinguish recording and transcription;
repeated presses during transcription do not start another recording.

* Fish shell
=modules/features/shell/fish.nix= owns Fish, its plugins, aliases, initialization, and
Starship and direnv integrations. Select =fish= without a separate =prompt= module.
Fish also installs =moor= for its =less= alias.
Secret loading remains in =modules/features/secrets.nix=.
Edit =modules/features/shell/starship.toml= for the prompt configuration; Home Manager links
it to =~/.config/starship.toml= as a read-only file. Back up an existing unmanaged
file on the first switch with =home-manager switch --flake . -b backup=.

* Linux development CPU priority
The global Cargo feature defines one systemd user =devbuild.slice= with
=CPUWeight=10=, compared with the usual sibling weight of 100. Concurrent
development sessions share this allocation. There is no hard CPU quota: builds
use idle CPU but yield a larger share to competing foreground work.
Darwin and the existing =CARGO_TARGET_DIR=/tmp/cargo-target= setting are unchanged.

Fish automatically runs =devenv= commands and ordinary =nix develop ...=
invocations through =dev-build=. The complete session and its descendants
inherit lower CPU priority, including whichever Cargo its toolchain selects.
Non-build commands inside that session also get lower priority. No project
devenv or flake changes are needed.

Scripts, agents, IDEs, absolute executable paths, =command nix=, and Nix options
before =develop= bypass these Fish functions. Use the helper explicitly at their
entry point:

#+begin_src sh
dev-build nix develop --command cargo build
dev-build devenv shell
#+end_src

Command proxies such as RTK also bypass Fish functions; use
=rtk proxy dev-build nix develop ...= instead of =rtk proxy nix develop ...=.

Direnv activation alone does not move the terminal into a cgroup. For Cargo
launched from an unscoped direnv-enabled terminal, use =dev-build cargo build=.
Nested helper calls reuse their existing build scope.

The host needs a running systemd user manager with the cgroup v2 CPU controller
delegated. Missing support is an error, not an unrestricted fallback. Inspect:

#+begin_src sh
systemctl --user show devbuild.slice --property=CPUWeight --property=ControlGroup
systemd-cgls --user-unit=devbuild.slice
#+end_src

Existing builds are not moved; restart through a scoped entry point.
Nix daemon workers and independently launched systemd services do not inherit
the client's scope. CPU weighting is not guaranteed latency protection, and
does not limit memory pressure, disk contention, or thermal throttling.
Removing the Linux additions and reactivating Home Manager restores normal
entry points; already-running scopes keep their policy until exit.

Wrapper checks run during its package build, or directly:

#+begin_src sh
python3 /home/christian-koestlin/.config/home-manager/modules/features/global-cargo-settings/test-dev-build.py
#+end_src

* Shared agent skills
=modules/features/agent-skills.nix= owns skill sources, selection, the upstream Home Manager
module import, and the generic =~/.agents/skills= target. =modules/features/claude.nix= and
=modules/features/copilot.nix= own their packages and respective skills targets.

=modules/profiles/common.nix= selects all three modules. Nix merges their declarations:
each target uses the same selected skills bundle in the Nix store, linked into
=~/.agents/skills=, =~/.claude/skills=, and =~/.copilot/skills=. No duplicated skill
definitions or content; add or remove skills only in =modules/features/agent-skills.nix=.
Agent-specific settings and instructions stay in their respective agent modules.

When composing a profile without =common=, select =agent-skills= alongside any
agent module. New agents need only their own target declaration, not a skill list.

* Feature-owned overlays
=modules/features/editor.nix= contributes the Emacs overlay; =modules/features/herdr.nix= contributes
the Rust overlay; =modules/features/nixgl.nix= contributes nixGL. =modules/flake/home.nix=
only declares and consumes the shared =overlays= option. Contributions still apply
globally to every home configuration, regardless of Home Manager feature selection.

* herdr Copilot detection patch
=patches/herdr-copilot-detection.patch= fixes detection of Nix-packaged Copilot
running as =node= or =MainThread=. Applied by =modules/features/herdr.nix=; includes
regression tests in upstream's =src/detect/mod.rs=.

Based on herdr =916fcf8de029c6cac965b50f3cdb9687cd7d1537=. In an upstream checkout:
#+begin_src sh
git apply /path/to/home-manager/patches/herdr-copilot-detection.patch
cargo test --locked --bin herdr detect::tests::identify_
#+end_src

Remove the local patch once the pinned upstream version includes the fix.
Building or switching Home Manager does not replace an already-running herdr
server; plan its restart separately, without interrupting active sessions.

Upstream currently accepts implementation PRs only from approved contributors.
Check its contribution policy before submitting; a local patch is not PR approval.
